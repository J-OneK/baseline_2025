# 从原始行为到 Top-10 的数据链路

本文沿着真实用户 RID **311428**、seed **2026** 跑完整条链路。目标广告是 OID **20004114747**，训练前缀中出现 **0 次**。主召回漏掉它，历史辅助通道补进 500 条候选，旧融合参考排第 494，当前纯 DCN V2 排第 3，联合 Transformer 排第 3。下文另用 RID 957879 展示联合排序把目标从第 14 提到第 8。

```text
Parquet 行 → 按时间清洗、切分 → 按 local ID 对齐的数组缓存
  ├─ 用户可见历史 → InfoNCE 用户查询 [B,32] → 全目录内积 Top-500
  └─ 最近已知行为 → 102/122 同组近邻 → 冷启动、长尾提议
                                ↓
   合并去重 [B,500] → 静态特征 [B,500,15] → 纯 DCN V2 基础分
                                ↓
     行为 token [B,40,24] + 每候选两组 token [B,500,2,24]
                                ↓
      联合 Transformer 残差 [B,500] → 总分排序 → Top-10 OID
```

下面 `B=1` 表示演示这一个用户。单走 Faiss 的召回演示使用同一内积分数的近似检索。本文的完整排序和确认实验使用精确 Top-500。 [三个阶段的指标口径](release.md)

## 1. 原始 Parquet 行与本地 ID

`seq/` 的每行是一个用户，`seq` 列是一组事件结构体。这名用户原有 24 条事件，以下是验证时间边界前最后三条在原始 Parquet 中的内容。原始 `item_id` 是广告 RID，`action_type=0` 表示曝光，`1` 表示点击。

```json
{
  "user_id": 311428,
  "seq": [
    {"item_id": 1738210, "action_type": 0, "timestamp": 1731591430},
    {"item_id": 3206824, "action_type": 1, "timestamp": 1731673950},
    {"item_id": 4590467, "action_type": 0, "timestamp": 1731674319}
  ]
}
```

`prepare.py` 过滤无效事件，稳定地排序并保留最后至多 100 条。它从合格的首次出现点击中选验证和测试事件。相同时间戳的事件不会进入当前目标的历史。该用户 `val_pos=10`、`val_cut=10`、`test_pos=11`，索引从零开始。验证请求只看 `[:10]`，目标点击在位置 10，广告 RID 为 4400700。

缓存里的事件按行靠左存放，尾部补零。广告按缓存目录重新分配连续的 local ID，动作转为 `1=曝光`、`2=点击`、`3=未知`，`0` 留作填充。上面的三条变为：

| 事件字段 | 第 8 条可见事件 | 第 9 条可见事件 | 第 10 条可见事件 |
|---|---:|---:|---:|
| 源 RID | 1738210 | 3206824 | 4590467 |
| 缓存广告 local ID | 559696 | 1031838 | 1477171 |
| 缓存动作码 | 1 | 2 | 1 |

排序实验的缓存有 93,586 名有效用户、1,538,730 个广告。常用文件如下。

| 缓存文件 | 实际形状与用途 |
|---|---|
| `items.npy`、`actions.npy`、`timestamps.npy` | 各为 `[93586,100]`。同一位置分别存广告 local ID、动作和时间戳 |
| `val_cut.npy`、`val_pos.npy` | 各为 `[93586]`。输入切在前者，留出点击取后者 |
| `item_sparse.npy`、`item_mm81.npy` | `[1538731,13]` 和 `[1538731,32]`。同一 local ID 对上属性和 81 号向量，第 0 行为保留行 |
| `item_id_lookup.npy`、`train_counts.npy` | 各为 `[1538731]`。前者映射到独立 ID embedding 的行，后者统计所有训练前缀事件 |
| `catalog_rids.npy`、`catalog_oids.npy` | 各为 `[1538731]`。local ID 为数组下标，可查源广告 RID 和输出业务 OID |
| `user_sparse.npy`、`user_array_106.npy` 等 | 单值字段为 `[93587,4]`，多值字段按字段长度补齐。106 的宽为 8 |

该用户在 `items.npy` 中是第 29015 行，模型用户编号是 29016。目标广告同时有 **源 RID 4400700、local ID 1415788、输出 OID 20004114747**。它的 `train_counts=0`，ID Embedding 查第 0 行，内容和可用属性仍可参与打分。 [清洗和缓存](../taac_retrieval/prepare.py) · [验证输入切分](../taac_retrieval/data.py)

## 2. 左补齐、编码和精确主召回

`SequenceDataset("val")` 先取历史，再放用户 token 并左补齐，所以进主召回器的是下面这种结构。用户 token 对应 `kinds=2`，广告事件对应 `kinds=1`，填充对应 `kinds=0`。每个数组长度为 101，批处理后是 `[1,101]`。

```text
items   [..., 0(用户占位), ..., 559696, 1031838, 1477171]
kinds   [..., 2(用户token), ...,      1,       1,       1]
actions [..., 0,           ...,      1,       2,       1]
user = 29016
```

因果序列编码器取最后一个有效历史位置的输出作为 `q:[1,32]`。实测 `q` 的前四维是 `[-1.193134,-0.142864,-0.411329,0.656099]`。广告塔导出 `[1538731,32]`，用原始内积 `q · v` 做分块精确检索并排除可见历史。返回 `candidates:[1,500]` 和 `scores:[1,500]`，同一列对应同一广告。

| 主召回名次 | local ID | OID | 内积分 |
|---|---:|---:|---:|
| 1 | 247239 | 20004281921 | 8.677027 |
| 2 | 941342 | 20005856461 | 8.524972 |
| 3 | 879095 | 20004234388 | 8.434607 |

目标广告不在返回列表中。 [主模型前向](../taac_retrieval/model.py) · [分块精确检索](../taac_retrieval/metrics.py)

## 3. 历史查组与候选合并

辅助通道拿最近 40 条已知曝光或点击查 102/122 属性组。目标本例与曾点击过的 local ID 1031838 的广告共享编码值 `102=3535` 和 `122=25920`，单位化 81 号向量的余弦为 **0.993804**。候选一开始按冷启动和长尾分别给出最多 80 条提议，形状为 `[1,2,80]`，不足位置用 0 补齐。

合并时防止历史广告与主候选重复，每桶最多补 5 个，替换未保护的低位候选。保护的是原排序 Top-100 **成员**和原来找到的冷尾广告。实际补了 10 条，`merged:[1,500]` 仍是 500 条唯一广告。目标有 `changed[0,499]=True`，即位于数组列 499。列是候选存放位置，排序分重新排序后，旧融合下它实际排第 494。 [提议与融合](../taac_retrieval/group_recall.py) · [全列表构造](../scripts/build_channel_features.py)

## 4. 每条候选变成 15 项数值特征

对原召回列表分别计算内积和内容 MLP logit 的均值、标准差。对保留广告和补入广告都用原列表的统计量做 z-score。合并后每个广告一行，批张量是 `x:[1,500,15]`。例如目标这行里有：

| 字段 | 本次实测值 | 含义 |
|---|---:|---|
| `retrieval_z` | -1.889562 | 用主列表均值和方差换算后的内积分 |
| `ctr_z` | +0.364688 | 冻结内容 MLP logit 的 z 分 |
| `train_events_log` | 0 | 全局训练事件次数的 `log1p` |
| `added_channel` | 1 | 由辅助通道补入 |
| `click_match_cosine` | 0.993804 | 候选与同组点击的最大余弦 |
| `exposure_match_present` | 0 | 可比的同组曝光向量缺失 |
| `best_match_age_log` | 1.967112 | 相距最后可见事件 369 秒，换算为 `log1p(369/60)` |
| `matched_fields` | 2 | 102/122 两个字段同时相同 |

旧融合分 `0.9 × retrieval_z + 0.1 × ctr_z` 为 **−1.664137**，仍用于合并时保护原 Top-100 成员。当前 DCN V2 直接在这 15 项上输出 **2.287390**，排第 **3**。两项旧分都是输入特征，但不再把旧融合分加在 DCN 输出上。 [15 个字段和时间计算](../taac_retrieval/channel_features.py) · [DCN V2](../taac_retrieval/channel_ranker.py)

## 5. 保留逐条历史并构造联合 Transformer 输入

| 数据 | 形状 | 一行/一个 token 表示什么 |
|---|---|---|
| 候选内容 | `[1,500,32]` | 每个候选的单位化 81 号向量。目标向量前四维是 `[0.244077,0.051758,-0.251663,-0.202176]` |
| 历史内容、动作与时间差 | `[1,40,32]`、`[1,40]`、`[1,40]` | 逐条历史查同一张广告内容表，再附上动作码和相对时间。本例有效行为 10 条，其余 30 个位置为左填充 |
| 历史 token | `[1,40,24]` | 内容线性投影加动作 embedding、位置 embedding 和时间投影 |
| 每候选的两个 token | `[1,500,2,24]` | 第一组是内容加 5 项基础特征，第二组是 10 项通道与匹配特征 |
| 联合分数修正 | `[1,500]` | 两层联合注意力后拼接两个候选 token，再线性映射为每个广告的一个标量 |

同一请求的候选复用一份历史投影。候选的 token 会读取有效历史与本候选内可见的 token。不同候选之间独立计算分数，它们在列表训练损失中相互竞争。能读到逐次行为，就有机会区分一次偶然的高相似匹配和连续多次相关点击。 [输入组装](../scripts/recommend_channel_rank.py#L129) · [联合注意力与打分](../taac_retrieval/sequence_ranker.py)

## 6. 从两个模型分数得到最终输出

该目标的实际分数链路为：

```text
纯 DCN V2 直接输出  2.287390 → 第 3
 + 联合残差        −0.041378
 = 最终分           2.246011 → 第 3
```

最后对同一个用户的 500 个总分降序排列，取前十，再把 local ID 从 `catalog_oids` 转回可展示的 OID。联合残差也会改变其他候选的分数，名次由整张列表的相对顺序决定。这个冷启动目标在加入联合残差前后都是第 3，说明辅助召回和纯 DCN 在此例中的作用。另一个真实用户 **RID 957879** 的目标 **OID 20002001783** 由主召回找到（第 19），纯 DCN 给出 **2.350007**（第 14）；联合模型加 **0.078511**，最终 **2.428518**（第 8）。单用户 HR@10 从 0 到 1，NDCG@10 从 0 到 `1/log2(9)≈0.315465`。多用户结论要看全队列。 [补入候选的 trace](../reports/sequence_base_ablation/demo_rid311428.json) · [提到前十的 trace](../reports/sequence_base_ablation/demo_rid957879.json) · [全体结果](../reports/sequence_base_ablation/README.md)

## 7. 训练的数据与演示数据如何对应

**主召回训练**把长度 101 的输入左补齐并构造移位目标。比如在某条广告的输出位置监督下一条广告。 `positive:[B,101]` 存真实下一条广告的 local ID，`target_actions:[B,101]` 标记该目标动作。挑出 `M` 个目标为点击的位置，每个位置从训练可见目录采 64 个候选并排除该用户的训练历史，得到 `negative:[M,64]`。一个正例的内积加 64 个负例内积拼成 `[M,65]`，以列 0 为标签做 InfoNCE。 [移位数据](../taac_retrieval/data.py) · [负样本、mask 与训练](../taac_retrieval/train.py) · [InfoNCE](../taac_retrieval/objectives.py)

**排序训练**使用已冻结的双通道召回列表和 15 项特征。历史位置的可见边界与打分一致。不同阶段的输入和目标整理为 `candidates:[B,500]`、`prior:[B,500]`、`features:[B,500,15]` 和 `target_position:[B]`。最后一个张量是在该列表里找到真实点击的列。例如 seed 2026 的实际训练缓存第一行，用户 RID 953 的目标 local ID 为 464660，位于第 7 列（从 0 开始）。因此交叉熵的类别标签是 7。这条候选训练频次是 129，正例权重为 1。冷启动和 1–5 次长尾的正例权重是 2。其余展示用户即便目标没进候选，仍保留在评估分母。 [直接打分的 DCN 训练](../scripts/ablate_channel_prior.py) · [联合排序重训与锁定](../scripts/ablate_sequence_rank.py)

## 本机查看同样的数据

```bash
python scripts/recommend_sequence_rank.py --device cpu --seed 2026 --rid 311428 --show-target --trace
```

`--trace` 展示形状、部分事件、候选与分数。加上 `--show-target` 后，分数复盘聚焦留出目标。平时仅用 `--trace` 会追踪最终排名第一的候选。目标审计在排序后执行。数据、模型和向量的准备见[排序入口](ranking_extension.md)。

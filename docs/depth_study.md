# Transformer 层数对照：1／2／4 层

本轮实验回答一个具体问题：**在当前推荐任务与训练设置下，一层序列网络是否限制了效果，增加到两层或四层是否值得？**

配置、训练计划和产物按 `depth_study` 命名。实际结果以[实验报告](../reports/depth_study/README.md)及其 `metrics.json` 为准；本文解释协议，不预先认定更深的模型一定更好。

## 1. 为什么先只改层数

现有网络融合广告 ID、13 个匿名属性和 81 号文本向量，再用因果 Transformer 编码用户历史。此前主要比较监督范围、损失和负样本数，主干采用隐藏维度 32、一个注意力头和一层 Transformer。

一层因果注意力已经允许最后位置读取所有更早的有效历史。增加层数增强的是多阶段特征交互，不会自动补足稀有广告缺失的点击正反馈。因此要同时查看总体指标、冷启动与长尾候选覆盖。

本轮固定 FFN 为 `32 → 32 → 32`，只比较层数。FFN 扩张、隐藏维度 32／64 和注意力头数属于之后的独立问题，本轮没有完成这些对照。

| 设置 | 对照 | 新实验一 | 新实验二 |
|---|---:|---:|---:|
| Transformer 层数 | 1 | 2 | 4 |
| 隐藏维度 | 32 | 32 | 32 |
| 注意力头数 | 1 | 1 | 1 |
| FFN 中间维度 | 32 | 32 | 32 |
| 历史动作 Embedding | 关闭 | 关闭 | 关闭 |
| 广告 ID 遮蔽率 | 0 | 0 | 0 |
| 目标 | 点击 InfoNCE | 相同 | 相同 |
| 每监督位置负样本数 | 64 | 64 | 64 |
| 温度 | 1 | 1 | 1 |
| batch size | 128 | 128 | 128 |
| epoch | 5 | 5 | 5 |
| 学习率 | 0.001 | 0.001 | 0.001 |
| 训练种子 | 2026／2027／2028 | 相同 | 相同 |

一层对照复用已完成的原始点击 InfoNCE 三种子训练；两层和四层分别新增三次训练。它们使用相同缓存、训练前缀、固定验证队列、候选目录和历史过滤规则。

## 2. 参数表很大，序列网络很小

本配置中，每多一层增加 **6,464** 个参数，包括注意力、FFN 和该层的两次 LayerNorm。Embedding 表与广告检索向量维度保持一致。

| 参数类型 | 1 层 | 2 层 | 4 层 |
|---|---:|---:|---:|
| Embedding 表 | 129,537,120 | 129,537,120 | 129,537,120 |
| 非 Embedding 参数 | 32,224 | 38,688 | 51,616 |
| 总参数 | 129,569,344 | 129,575,808 | 129,588,736 |

参数量几乎不变，不代表计算量相同。每增加一层，历史编码会多做一次注意力和前馈计算；训练耗时、显存及覆盖评估成本仍需实测。报表把这些成本与效果一起列出。

实现来源：[当前模型](../taac_retrieval/model.py)、[复用的注意力与 FFN](../model.py)。

## 3. 为什么相同 seed 还不够

构造更多层会消耗更多初始化随机数。如果只把 `blocks=1` 改为 2 或 4，即使 seed 相同，一些公共参数也可能从不同随机值出发。

[initialization.py](../taac_retrieval/initialization.py) 按下列过程准备初始权重：

1. 根据历史一层模型的配置，用原种子重新构造尚未训练的一层模型。
2. 按原参数遍历顺序计算初值 SHA，并与历史训练配置保存的摘要核对。
3. 保存一层模型构造后的 CPU RNG 状态。
4. 在 CPU 随机状态隔离区中，以 `seed + 101` 构造四层模板。
5. 用已经核对的一层初值覆盖四层模板的所有公共参数，包括广告／用户／属性 Embedding、投影、第一层、归一化和动作表。
6. 两层模型加载模板前两层所需参数；四层模型加载完整模板。两者也共享第二层的初始参数。

这里加载的是**初始权重**，没有使用训练后 checkpoint 做暖启动。静态特征 buffer 不属于可训练参数状态，仍从相同缓存读取。

```text
原 seed → 重建一层初始模型 → 核对历史初值 SHA
                              ↓ 复制全部公共参数
CPU seed+101 → 四层初始模板 ──┼→ 两层模型所需子集
                              └→ 四层模型完整状态
```

不同层数的完整参数集合不同，因此不会要求完整模型摘要相同。报告逐参数核对：

- 一层与两层／四层的所有公共参数相同。
- 两层与四层的公共参数相同，包括第二层。
- 新配置的公共初值摘要与历史一层初值摘要相同。
- 参数形状、缓存签名和初始权重文件身份匹配。

CPU RNG 会恢复为原一层构造后的状态；数据打乱与负采样继续使用各自的独立生成器。更深网络在前向传播中会自然消耗更多普通 dropout 随机数，所以实验不声称各层数的全部 dropout 轨迹逐步相同。

## 4. 评估与选择规则

每次训练都跑完整五轮，只在相同验证用户上评估，不用测试指标选择 epoch。

- 单次运行的最佳 checkpoint：先比较整体验证 NDCG@10，再比较 HR@10，完全相同时保留较早 epoch。
- 层数选择：比较三个种子的平均最佳验证 NDCG@10，再比较 HR@10，再选择较少层数。
- 诊断：固定每个 checkpoint，在完整目录精确检索 Top-500，报告所有分组的 Recall／NDCG@10、@100、@500。
- 复核：按同一用户、同一种子配对报告相对一层模型的差值和 bootstrap 区间。
- 附加记录：固定第 5 轮的验证指标、训练曲线、时间、显存和参数分解，避免只展示最好的一个数。

冷启动、长尾、中频和头部继续按目标广告在所有训练前缀中的事件次数划分：0、1–5、6–50、超过 50。当前每名用户只有一个相关目标，所以 Recall@K 与对应单目标 HR@K 数值相同。

这批验证用户此前已经用于开发，本轮属于架构开发实验。三个训练种子有助于观察稳定性，但不能代表所有随机初始化；配对区间也不构成新的独立测试确认。本轮不构造测试 Dataset，不自动替换现有推荐模型、广告向量或 Faiss 索引。

## 5. 输出与复现

| 位置 | 内容 |
|---|---|
| `configs/depth_study.json` | 固定层数、训练设置、初始化与选择规则 |
| `artifacts/depth_study/plan.json` | 参考产物、初始权重、任务配置及源码摘要 |
| `artifacts/depth_study/initialization/` | 三个种子的共享初始状态及逐参数摘要 |
| `artifacts/depth_study/training/` | 新两层／四层运行、checkpoint、逐轮验证和日志 |
| `artifacts/depth_study/diagnostics/` | 三种深度、三个种子的验证 Top-500 与逐用户结果 |
| `reports/depth_study/` | 结果、选择、校验和图表 |

在仓库根目录使用当前 `.project_venv`，新复现使用未占用的输出目录：

```bash
.project_venv/bin/python scripts/run_depth_study.py \
  --root artifacts/depth_study_reproduction \
  --report-dir reports/depth_study_reproduction \
  --config configs/depth_study.json \
  --gpus 0,2,3,4,5,6
```

一张 GPU 可使用 `--gpus 0`，任务将排队。这个入口依赖已经准备好的扩大缓存、冻结队列和历史一层参考运行；它不重复下载数据或改写历史训练结果。

| `--stage` | 执行范围 |
|---|---|
| `all`，默认 | 准备初始状态与计划，训练，覆盖诊断，汇总报告 |
| `prepare` | 仅准备并核对嵌套初始状态与冻结计划 |
| `train` | 准备／复核计划并完成两层、四层训练 |
| `finish` | 在训练已完成后继续覆盖诊断与报告 |

计划冻结后，配置、参考产物或训练源码发生变化时，应改用新 `--root`。没有保存完整 optimizer 状态供任意 batch 无损恢复；这里的复用是复用已完成且匹配的实验产物。

代码入口：[实验编排](../scripts/run_depth_study.py)、[共享初值](../taac_retrieval/initialization.py)、[训练](../taac_retrieval/train.py)、[覆盖诊断](../taac_retrieval/coverage.py)、[结果核对与报告](../taac_retrieval/depth_report.py)。

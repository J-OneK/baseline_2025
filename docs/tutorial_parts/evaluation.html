6.3 为什么分块搜索仍然是精确 Top-K？

如果一次建立 [256, 2_708_122] 的 float32 分数矩阵，仅分数就约为 2.58 GiB。当前实现每次处理 32,768 个广告，单块分数约 32 MiB。广告向量本身、模型与其他中间张量仍需要额外内存。

{{code:taac_retrieval/metrics.py:40:60}}
  1. start=1：跳过 padding 行 0。
  2. queries @ item_vectors[start:end].T：计算当前广告块与所有查询的内积分数。
  3. 把当前历史中出现过的广告分数改为负无穷。它们仍在公共目录里，但当前用户不会再次收到它们。
  4. 取这个块的 Top-K，与此前维护的全局 Top-K 合并，再选 K 项。
  5. 全部广告块遍历完后，检查是否确实有 K 个有限分数的合法候选。
TopK(A ∪ B) = TopK(TopK(A) ∪ TopK(B))

这个等式可以用反证理解：某个广告如果在自己所在的块中已排在第 K 名之后，那么同一个块内至少 K 个广告分数不低于它，它就不可能挤进全局前 K。分块省下分数矩阵的峰值空间，但仍计算所有合法候选的分数。对边界同分广告，具体 ID 的先后可能取决于 Top-K 的同分处理；分数最优性仍成立。

6.5 HR、Recall、Precision 和 NDCG 的公式

令 ru 为目标广告的一基排名，即第一名的 r=1。当前协议每个用户只有一个目标点击，定义指示函数 𝟙[条件]：成立时为 1，否则为 0。

HR@K = (1 / U) ∑u=1…U 𝟙[ru ≤ K]

HR 是“多少用户的目标进入了前 K”。标准 Recall 是“找回的相关项数 ÷ 全部相关项数”；这里每人恰好一个相关目标，所以单目标 Recall@K 与 HR@K 数值相同。Precision@K 的分母是推荐列表长度 K：一次命中时 Precision@10=1/10，并不等于 HR@10。

DCG@K = ∑j=1…K relj / log2(j+1)  ;  NDCG@K = DCG@K / IDCG@K

这里使用二元相关性：真实目标位置 rel=1，其他位置为 0。理想排序把唯一目标放在第一名，因此 IDCG=1/log₂(2)=1，公式化简为：

NDCG@K = (1 / U) ∑u=1…U 𝟙[ru ≤ K] / log2(ru+1)

这一章的自测

训练中只采 64 个负例，为什么评估还要算全部候选？

采样损失提供高效学习信号，但目标在采样集合内排第一，不代表在整个目录内也靠前。主报告用固定全候选库，使不同模型的评估难度一致。

目标排第 3 名时，为什么 NDCG 是 0.5？

唯一相关项的理想 DCG 为 1；实际折扣为 1/log₂(3+1)=1/2。若 K 小于 3 则目标被截断，NDCG@K 为 0。

分块搜索漏算了块之间的交互吗？

每个用户—广告分数是独立的内积。块内保留前 K、块间再合并前 K，足以得到所有分数的全局 Top-K；并不需要候选彼此之间的分数。

当前用户从没见过某广告，就能把它归为 cold_0 吗？

不能。cold_0 要求它在所有用户的训练前缀中出现次数为零；当前用户未见只是历史过滤的条件。

7.2 原始内积与余弦相似度

qTv = ‖q‖ · ‖v‖ · cos θ  ;  cosine(q,v) = qTv / (‖q‖‖v‖)

训练优化的是原始内积分数，向量长度也是模型学到的信号。直接把所有广告归一化为单位向量，会移除广告范数对分数的影响，可能改变排名。

教学例：q=(1,0)，广告甲 x₁=(1,0)，广告乙 x₂=(3,1)。

广告原始内积余弦
甲11
乙33/√10 ≈ 0.9487

内积优先乙，余弦优先甲。因此当前代码没有进行单位归一化。若要改成余弦，需要把它作为新的建模/检索实验验证，而不能静默替换。

7.3 为内积排序构造一个等价的欧氏距离问题

MIPS 是 Maximum Inner Product Search，即最大内积检索。历史直接使用 raw-IP HNSW 的验证召回没有达到 98% 门槛，因此采用一个保持精确排名的非对称变换。先选定覆盖全部广告范数的半径平方：

R² = maxi ‖vi‖²

广告向量增加一维，用户查询也增加一维，但构造方式不同：

v′i = [vi, √(R² − ‖vi‖²)]  ;  q′ = [q, 0]

展开两者的平方欧氏距离：

‖q′−v′i‖² = ‖q−vi‖² + R² − ‖vi‖²
= ‖q‖² + R² − 2qTvi

对一次固定查询，‖q‖²+R² 是与广告无关的常数。因此距离越小，原始内积越大。模型仍输出 32 维向量，HNSW 内部索引维度是 33。

{{code:taac_retrieval/ann.py:6:26}}

radius_squared 必须不小于任一广告向量的范数平方；maximum(...,0) 处理舍入误差，不能靠它掩盖明显不合格的半径。Faiss 的 L2 搜索返回平方距离，包装类把它还原为原始内积分数：

score = (‖q‖² + R² − distance²) / 2

手算 q=(1,0)，R²=10：

广告原向量广告升维向量与 q′=(1,0,0) 的平方距离还原内积
(1,0)(1,0,3)9(1+10−9)/2=1
(3,1)(3,1,0)5(1+10−5)/2=3
(0,2)(0,2,√6)11(1+10−11)/2=0

变换保证的是精确距离排名与精确内积排名等价。HNSW 仍然是近似搜索，不能由这条代数恒等式推出它必定找回 100% 的精确结果。实际近似质量要测量。

7.4 HNSW 的三个参数，以及验证门槛

HNSW 把广告向量组织成多层邻接图。上层提供较远距离的跳转，搜索再逐层深入，在底层维护候选集合。它以额外图结构内存和建索引成本，换取查询时少访问许多向量。

efSearch2048查询时的搜索宽度；通常越宽越慢，但更有机会找到精确近邻

7.5 Faiss 行号、历史过滤与多取候选

索引构建时从 item_vectors[1] 开始，跳过补齐行。Faiss 自动分配从 0 开始的行号，因此完整编号链是：

Faiss row 0 → local ID 1 → catalog_oids[1] → 最终广告 OID
{{code:taac_retrieval/ann.py:29:55}}

filter_results() 依次把 Faiss 行号加 1，删除负行号、当前用户已见广告和重复广告，按原检索顺序保留前 K。它不训练新的分数函数，也不使用真实目标来调整列表。

直接查询十个候选，可能被历史过滤删掉若干个。因此 search_filtered() 请求：

fetch = min(N, K + 当前 batch 中最大的非零历史事件数)

例如主样例测试历史 [1,2,3,4,5,6,6,7] 有 8 个非零位置，尽管只有 7 个不同广告，代码仍按 8 计数；请求 Top-10 时会多取到 18 个，以留出过滤空间。重复历史会造成保守地多取一些候选。

这里实际只检索一次，没有“候选不足就自动循环扩大搜索”或热门广告兜底。过滤后不足 K 个会抛出异常。理解当前保护范围，才能在扩展服务时知道还缺什么。

这一章的自测

32 维模型为什么会保存一个 33 维索引？

广告增加 √(R²−‖v‖²) 一维，查询增加 0 一维，把最大内积转换为最小平方欧氏距离。包装类对外报告的逻辑维度仍为 32。

如果查询网络换成新训练模型，旧索引能继续用吗？

同一个维度不保证向量空间一致。应使用新 checkpoint 重导出广告向量并重建索引；当前 SHA 检查会拒绝普通的模型身份混用。

Faiss 返回 0，可以直接当作 padding 丢掉吗？

不能。索引跳过了向量表 padding 行；Faiss 的 0 对应 local ID=1。负返回行号才是无效项，之后还要做历史与重复过滤。

98.81% ANNRecall 能说明 98.81% 的用户点击被找到了吗？

不能。它说明近似列表与同模型精确列表高度重合。真实目标命中由 HR/Recall/NDCG 单独衡量。

阶段 08 · 用证据理解取舍

读懂真实实验，而不是只记一个提升百分比

学习目标：说明基线到主方案改变了哪些因素，区分开发验证、独立确认与后续探索；把每个数字绑定到具体模型、队列、种子和测量范围。

8.1 主召回如何选定 InfoNCE-64？

开发阶段先在较小数据缓存上比较监督、损失、负例数量和动作输入的组合，只根据平均验证 NDCG@10、再 HR@10 锁定 click_infonce64。随后扩大到 280,985 个有效用户，构造排除此前已查看测试用户的 10,000 人新队列，用三个种子确认基线与选定方案。

8.3 为什么保存逐用户预测和多个种子？

同一用户对两种模型的评估难度相似，所以比较时应配对。令 ds,u 为种子 s、用户 u 上“选定方案指标减去基线指标”，先平均得到观察差值，再通过有放回重采样估计不确定性：

Δ = (1 / (S·U)) ∑s=1…S ∑u=1…U ds,u
{{code:taac_retrieval/objective_report.py:17:29}}

paired_user_95pct 在当前种子集合下重采样用户；paired_seed_and_user_95pct 同时重采样当前三个种子和用户。两种模型始终使用同一抽样下标，保留配对关系。历史主测试的 NDCG 绝对差在“用户 + 种子”方式下的 95% 区间为 [0.002960731, 0.006803916]。

这描述了当前数据与当前三个训练种子的证据不确定性。三个种子不能代表所有初始化；bootstrap 也不会制造新的独立数据集。看过测试之后再提出的新策略，即使再次在这批测试用户上测量，也属于后续研究，不能称为全新的独立确认。

报告还核对六次确认训练的完整五轮预算、checkpoint 是否按验证选取、逐用户目标与行号是否一致、共同初值 SHA 是否匹配、训练是否跳过测试。这样的记录让“同口径比较”可以从产物中复查。

这一章的自测

能把基线到主方案的 46.19% 都称为 InfoNCE 的纯损失收益吗？

不能。基线到主方案同时改变曝光监督、负例数量和损失。固定点击监督及 64 负例预算的 click BCE-64 对照，才更直接帮助分析损失形式。

三种子 NDCG=0.015391 与单模型 NDCG=0.014665 哪个应该写在演示旁边？

演示 seed=2026 checkpoint 时，应写单模型指标；主实验比较表可以写三种子均值，并明确统计方式。它们都是有效数字，但归属不同。

四层最佳验证均值领先，为什么主分支仍固定一层？

深度实验是复用验证集的开发结果，差值区间跨 0，最后一轮与最佳 checkpoint 结果还存在差异。没有独立测试和对应索引链路确认，因此保持证据完整的一层主版本。

冷启动候选覆盖变好，但原 Top-10 完全相同，意味着什么？

说明那一轮的旧排序把新增候选留在了榜尾。候选覆盖要和最后十条的效果分别报告。后续固定同一候选集，才可以检验 DCN V2 或联合残差的实际排序收益。

原始数据、特征与四层编号

模型最终处理的是整数和浮点数组。第一件事是说明这些数字来自哪张表、怎样连接起来，以及某个整数究竟是广告编号、特征类别，还是数组下标。

这一章的目标

能画出行为、用户、广告和内容向量的关联；能区分单值特征、多值特征和连续向量；能追踪一条广告从 OID 到模型 ID Embedding 的完整路径。

一份推荐数据集，由多张表共同描述

本项目从 TencentGR-1M/ 读取 Parquet。Parquet 是列式文件格式：同一目录可以有多个分片，PyArrow 将这些分片作为一张表扫描。每行可以包含整数，也可以包含列表或嵌套结构。下面的内容用 Python 字典展示表中一行的逻辑结构，原始存储格式仍然是 Parquet。

同一广告，为什么会出现四套整数

原始数据已经做过官方重映射；为了只存储抽样目录，项目又生成自己的紧凑映射；为了不给未训练广告分配独立ID参数，又增加一个训练ID查找表。它们依次承担不同工作：

名称谁生成解决什么问题查找方式
OID数据集提供的原始标识关联内容向量、输出最终广告标识indexer['i'] 提供 OID→RID
RID官方映射行为表和属性表中的整数键rid_to_local[RID] 得到 local ID
local IDprepare.py让本项目数组按0…N紧凑存储catalog_rids[local]、catalog_oids[local] 反查
ID Embedding 行号训练频次决定只给训练可见广告分配独立ID参数item_id_lookup[local]

官方映射中的实际例子是 indexer['i'][20004268480] = 1，即某个广告OID对应官方RID 1。它在本项目是否出现、被映射到哪个local ID，要由本次抽样目录决定，不能从这个映射单独得出。

一个明确标为合成的映射例子
本次目录的 catalog_rids = [0, 2, 6, 9]
所以：RID 2 → local 1；RID 6 → local 2；RID 9 → local 3

若 train_counts = [0, 3, 0, 7]，则
item_id_lookup = [0, 1, 0, 2]

RID 6 → local 2 → ID Embedding 第0行（训练未见，共享OOV）
RID 9 → local 3 → ID Embedding 第2行（训练见过）

训练未见广告依然有目录行、OID和静态属性，也可以被内容编码器计算向量。它没有独立的训练ID参数；能否被成功推荐，要由共享属性与内容分支的泛化能力决定。

同时间戳为什么要用 searchsorted(left)

pos 是目标事件在数组中的位置，cut 是可见历史的右开边界。时间唯一时常常相等；有相同时间戳时则不同。

times = [10, 20, 30, 30, 40]
# 下标     0   1   2   3   4

目标 pos=3，时间30
cut = searchsorted(times, 30, side='left') = 2
历史使用 clean[:2]，只有时间10、20
可见历史 H(t) = {事件 e | time(e) < t}

稳定排序只保证同一时间戳内保留原顺序，无法证明它们真的先后发生。严格小于目标时间，才能避免把同时发生的事件当作可用过去。验证目标也必须严格早于测试目标；即使存在两个合格点击，如果都在同一时刻，仍可能无法完成切分而返回 None。

评估假设必须讲准确

该项目采用已知公共静态目录的离线实验：广告ID和内容目录可提前知道，但用户的留出行为不进入训练历史。这属于代码中写明的 transductive public static catalog 假设。它没有做到所有用户共享一个全局时间截止点，也不等同于真实生产系统未来新广告上线的回测。静态目录已知与使用未来点击训练参数，是需要分别判断的两件事。

缓存中的 item_id_lookup 把计数大于0的广告映射到1开始的独立Embedding行；未训练广告映射到0。后续检索目录仍保留所有广告，编码时再使用这张表。

为什么还要 freeze_cohort()

{{code:taac_retrieval/cohorts.py:13:32}}

早期100,000抽样实验已经查看过2,000名用户的测试表现。扩大实验时，代码先从大缓存中按源表中的用户RID排除这2,000名用户，再用种子3107选择10,000名用户，保存固定行号与SHA256。主训练、评估和不同种子模型使用同一个固定队列。

验证与测试使用的是这同一批10,000名用户的不同时间目标，不是互不相交的两批用户。扩展的三种子确认阶段用新队列减少先前小实验测试反馈的影响；后来的冷启动和深度研究又复用了验证队列，其结论属于开发探索。

自检：为什么items数组里出现验证目标，不等于训练看到了验证点击？

完整数组是统一存储容器。训练实际取 items[:train_cut]；目标虽存在于后面的存储位置，但不进入训练上下文或训练监督。另一方面，全保留序列会影响静态目录的存在性，所以该协议仍应描述为已知公共目录的逐用户时间留出。

自检：min_history=5为何不保证至少有5个点击训练样本？

它统计的是严格更早的有效事件数，曝光和未知事件也计数。主模型之后只在目标动作编码为2的位置计算损失，某个合格用户甚至可能没有有效训练点击位置；训练循环会跳过整批有效位置数为0的情况。

数组缓存告诉我们事件在哪里，SequenceDataset 则决定模型在每个位置看到什么、预测什么。这一章用相同教学用户，把补齐、用户token、下一事件移位和点击监督逐列展开。

这一章的目标

能手写train/val/test三种样本；能区分历史动作与目标动作；知道用户token为什么用广告0占位；能解释负采样排除的seen为什么比移位后的输入多一个末尾事件。

make_input：左补齐 + 显式用户token

{{code:taac_retrieval/data.py:35:47}}

历史上限为 H 时，输入长度固定为 L=H+1，多出来的位置用于用户token。保留历史放在最右侧，用户token放在历史前一格，剩余左侧位置是PAD。

start = (H + 1) − 历史事件数 − 1

主配置 H=100，所以 L=101；下面演示 H=10、L=11，算法完全相同。

数组它描述什么0/1/2等编码
items这个位置的广告local ID真实广告大于0；PAD和用户token的广告ID占位均为0
kinds这个位置的token类型0=PAD、1=广告、2=用户token
actions这个输入事件的历史动作0=PAD/用户、1=曝光、2=点击、3=未知

用户token位置的 items=0 不表示它是PAD；模型依据 kinds=2 把用户属性编码放进去。user 字段提供内部用户行号，且 user=row+1，为第0行留出占位。

actions 与 target_actions 错一格，因为一个描述当前已观察输入，一个描述下一事件的标签。把它们混用，会把“当前输入是否点击”误当成“目标是否点击”。主模型不额外加历史动作Embedding，但仍然保留这些标签用于监督选择与对照实验。

seen：整个训练前缀的排除集合

训练样本的 seen = [1,2,3,4,5,0,0,0,0,0]
移位后的输入广告 = [1,2,3,4]
它们不完全相同：seen还包含前缀末端广告5。

负采样要排除这个用户整个训练前缀中见过的广告。否则最后一个训练事件可能被误当作同一用户其他位置的负例。该策略也会排除某个较早训练位置之后、但仍处于训练前缀内的广告；这属于当前训练负例定义，不能声称每个训练位置的负采样只参考该位置之前的历史。

真实负例池来自 train_counts>0 的全局训练可见广告，并从中均匀采样。当前代码允许重复抽中同一负例，所以64个负例是64次采样，不保证64个不同广告。它不读取验证和测试目标来“特别避开答案”。具体损失和采样拒绝逻辑见后续训练章节。

验证与测试：保留完整合法历史，预测一个留出目标

验证、测试不会把历史再右移一格。它们直接把该阶段的完整前缀传入 make_input()，让最后一个历史广告对应的位置产生用户查询向量。

# 验证：cut=5，目标广告6
items   = [0,0,0,0,0,0,1,2,3,4,5]
kinds   = [0,0,0,0,0,2,1,1,1,1,1]
actions = [0,0,0,0,0,0,1,2,3,1,1]
target  = 6

# 测试：cut=8，目标广告8
items   = [0,0,0,1,2,3,4,5,6,6,7]
kinds   = [0,0,2,1,1,1,1,1,1,1,1]
actions = [0,0,0,1,2,3,1,1,2,2,1]
target  = 8

注意验证输入最后一个广告是5，而不是4。训练中的移位是为了产生多个下一事件监督；验证和测试则需要用完全部可见历史。主模型的 predict() 取序列最后一格表示，因此左补齐也让“最后一格就是最新真实历史”保持一致。

一个样本怎样成为 batch

PyTorch DataLoader把多个用户样本堆叠：单用户 items 从 [L] 变成 [B,L]，用户行号从一个整数变成 [B]。在主配置中 L=101，训练 B 通常为128；最后一个batch可以更小。

字段单用户一批用户说明
items / kinds / actions[L][B,L]模型的序列输入
user / row标量[B]模型用户行号 / 缓存0起始行号
positive / target_actions[L][B,L]仅训练样本的逐位置目标
seen[H][B,H]仅训练样本的负采样排除历史
target标量[B]验证/测试每用户唯一的留出广告

模型先产生 [B,L,32] 的全部位置状态。点击mask再选出 M 个有效位置，得到 [M,32]。M 是该batch内的监督位置数，不等于用户数B；教学用户贡献1个位置，别的用户可能贡献多个或零个。

自检：用户token与PAD的items都是0，模型怎么区分？

看 kinds。PAD的kinds=0、用户token的kinds=2；模型用后者注入 encode_users(user)，并用前者处理有效位置与注意力掩码。广告ID数组的0只是这个槽位没有广告ID。

自检：教学用户到底在哪个位置计算click-only损失？

H=10时，只有数组下标7的target_actions为2且positive非0。这个位置的输入广告是1，目标是2。下标8的输入广告2虽然发生过点击，但它预测的下一目标广告3是未知动作，因此该位置不参与主方案的点击损失。

自检：若训练前缀为[A,B,C]，忽略PAD后应当怎么对齐？

输入为 [U,A,B]，positive为 [A,B,C]。用户token预测A，A位置预测B，B位置预测C；哪些预测位置贡献损失，仍由对应target_actions决定。验证时若合法历史为[A,B,C]，输入则使用 [U,A,B,C]，并在最后一格预测独立留出目标。

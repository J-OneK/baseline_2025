6.2 为什么分块搜索仍然是精确 Top-K？

如果一次建立 [256, 2_708_122] 的 float32 分数矩阵，仅分数就约为 2.58 GiB。当前实现每次处理 32,768 个广告，单块分数约 32 MiB。广告向量本身、模型与其他中间张量仍需要额外内存。

{{code:taac_retrieval/metrics.py:40:60}}
  1. start=1：跳过 padding 行 0。
  2. queries @ item_vectors[start:end].T：计算当前广告块与所有查询的内积分数。
  3. 把当前历史中出现过的广告分数改为负无穷。它们仍在公共目录里，但当前用户不会再次收到它们。
  4. 取这个块的 Top-K，与此前维护的全局 Top-K 合并，再选 K 项。
  5. 全部广告块遍历完后，检查是否确实有 K 个有限分数的合法候选。
TopK(A ∪ B) = TopK(TopK(A) ∪ TopK(B))

这个等式可以用反证理解：某个广告如果在自己所在的块中已排在第 K 名之后，那么同一个块内至少 K 个广告分数不低于它，它就不可能挤进全局前 K。分块省下分数矩阵的峰值空间，但仍计算所有合法候选的分数。对边界同分广告，具体 ID 的先后可能取决于 Top-K 的同分处理；分数最优性仍成立。

6.4 辅助通道：从同组广告里补冷启动与长尾

只考虑全体用户训练前缀中出现 0 次（冷启动）或 1～5 次（长尾）的广告，且候选要有非零 81 号向量。从该用户最近最多 40 条已知点击或曝光中，拿字段 102 或 122 到倒排表查同组广告。已经出现在可见历史中的广告被过滤。

辅助分 = max同组历史 h[cos(81候选, 81h) + 0.04 · 𝟙[h 是点击]]

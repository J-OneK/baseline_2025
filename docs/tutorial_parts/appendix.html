自测：如果把InfoNCE负例从64改成256，哪些结论需要重新验证？

计算与内存预算、采样难度、loss的均匀基线ln(K+1)、训练信号和最优epoch都可能变化。模型维数和打分函数本身未必改变，但必须重新训练并做同协议评估；不能把原checkpoint的精度和新训练设置拼成同一个结果。若要归因于损失形式，还需要对照负例预算。

自测：冷启动目标没有出现在主召回 Top-500，要先查哪里？

先查辅助近邻是否提议、固定预算合并后是否保留，再比较两层排序的名次。历史同组通道能补入主召回漏掉的广告，两层排序只能为合并后的 500 条打分。合并时保护的是原融合 Top-100 的成员，最终排序会重新比较全部 500 条。

变量、公式符号与推荐术语

符号本教程含义主方案取值或形状
B一个batch中的用户序列数训练默认128；评估默认256
H / L召回保留历史上限与含用户 token 的长度H=100，L=101。教学例 H=10，L=11
排序特征一条候选一行。召回分、CTR logit、频次和匹配等[B,500,15]
联合排序 token历史行为与每条候选的两组特征历史 [B,40,24]，候选 [B,500,2,24]
D模型的用户/广告表示维数32
M（训练公式）整批经过点击掩码后留下的监督位置数随batch变化，不等于B
M（HNSW参数）图索引的连接度配置主方案32；与监督位置数M无关
N固定广告目录中非padding广告数召回历史确认 2,708,122，排序确认目录 1,538,730，合成演示 106
K在Top-K指标里为推荐列表长度；在负采样公式中可代表负例数候选预算 500，最终显示 10，主训练负例 64
q / v / s用户查询向量 / 广告向量 / 原始内积分数q,v∈ℝ³²，s=qᵀv
τInfoNCE温度，先将logits除以它1.0
R²覆盖所有数据库向量范数平方的升维半径平方索引构建时从广告向量计算
r目标的一基排名第一名r=1，单目标NDCG=1/log₂(r+1)
Embedding / 稀疏特征
把离散类别编号映射为可学习向量。编号大小不表示类别之间的距离；每个字段拥有自己的查表空间。
Padding / OOV / 用户token
Padding补齐长度；OOV表示训练词表未知值；用户token承载用户属性。它们可能都在某些数组里写0，但语义由lookup、kinds、padding_idx及其他特征共同决定。
因果掩码
限制每个输入位置只读取自己和更早的有效输入；与训练目标移位配合，防止当前位置读取它要预测的未来广告。
Logit / Softmax / 交叉熵
Logit是归一化之前的分数；softmax把一组分数映射为和为1的相对概率；以正例所在位置为标签的交叉熵为−log正例概率。InfoNCE 将正例固定在第 0 列。列表排序的标签是留出点击实际所在列。
负例与未观察反馈
这里的负例是采样的训练可见广告，并未逐一证明用户讨厌它们。不能把采样负例都解释成用户曝光后明确不点击的广告。
召回与排序
InfoNCE 和历史同组近邻从全目录选候选。对固定 500 条，原融合分加 DCN V2 和联合 Transformer 的残差后得到 Top-10。
DCN V2 残差
对每条候选的 15 项汇总特征做显式交叉，预测一项加到原融合分的修正。
OneTrans 风格联合残差
候选的两组特征 token 读取用户的一条条历史行为，输出加到 DCN V2 基础分的修正。
精确检索 / ANN
精确检索计算完整目录分数并得到Top-K；近似检索用索引减少搜索开销，可能改变返回结果，因此要对照精确结果测量重合率。
验证集 / 测试集 / cohort
验证用来选epoch、方案或索引参数；测试用于锁定后评估；cohort是固定的评估用户集合。反复在同一验证队列试策略会增加选择偏差，需要独立确认。
种子 / 配对对照 / Bootstrap
种子控制初始化、打乱和采样等随机过程；配对对照尽量复用相同用户和条件；bootstrap重采样估计不确定性。用户数大不能消除少量训练种子造成的波动。
静态目录 / transductive协议
当前目录和静态内容来自公开快照，候选包含训练未见广告。逐用户严格截断历史，并不等价于把所有用户按一个全局时间点切开的生产回测。
Checkpoint / Buffer / 缓存
Checkpoint保存学习到的状态与配置；非持久buffer里的全量静态特征不进入state_dict；对应数组缓存仍必须可用并正确对齐。

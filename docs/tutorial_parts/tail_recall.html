12 · 历史对照：零点击长尾补充召回

保留原主模型，再补一条专门找长尾的通道

这一章从你已经理解的“用户向量 q 与广告向量 v 做内积”出发，解释后来新增的辅助召回：为什么只处理零点击长尾、怎样复用原模型、如何在固定500个候选内融合，以及实际找回了什么、付出了什么代价。读完后，你应该能沿着同一个广告追踪资格筛选、向量生成、子集检索、候选融合和最终评估。

本章属于 research/tail-recall 研究分支，来源提交为 d0b7374。前面讲的主分支训练与 Faiss 推荐仍按原方式运行；新增通道没有自动接入主项目的默认 Top-10 出口。本页嵌入研究源码与报告快照，离线阅读时也可以核对。

12.1 先把目标说清楚：补回主通道漏掉的一小部分

想象主通道是一位擅长整体推荐的检索员。它能在整个广告目录中找到较好的候选，却容易忽略只有很少历史、尤其从未收到训练点击的广告。我们不要求第二位检索员独立完成全部工作，而是给它一个更窄的任务：只在零点击长尾目录中，找一些主通道没找到的新候选。

判断辅助通道时，要问“它额外补回了什么”，而不是只比较它单独的总体命中率。两个通道各自命中100个目标，如果命中的完全是同一批，合起来也没有新增；辅助只命中10个、却全是主通道遗漏的目标，才存在互补的可能。但候选预算固定时，它也可能挤掉原有命中，所以新增与丢失必须一起看。

候选净增命中 = 新增命中数 − 丢失命中数

此前按点击支持缩放 ID、训练时随机遮 ID 的尝试，改善过部分长尾，但让单通道的冷启动表现退步。这不等于“辅助通道没有价值”。本轮换成保留原主结果、少量补尾的设计，直接研究候选增量与替换代价。

12.2 “零点击长尾”里的两个计数，不是同一个东西

对每个广告 i，先统计所有用户训练前缀里的信息。ni 是事件次数，曝光、点击和未知事件都算；ci 是其中的点击次数。留出的验证和确认点击不能回填进这些计数。

广告分组训练事件次数 ni训练点击次数 ci本轮进入辅助目录吗？
真正冷启动00不进入；原主列表中的冷广告受保护
零点击长尾1～50进入，本轮只补这一组
有点击长尾1～5至少1不进入；原主列表中的这一组受保护
中频或头部大于5任意合法值不进入辅助目录
辅助资格池 E = { i | 1 ≤ ni ≤ 5 且 ci = 0 }

例如广告 A 在训练里有3次曝光、没有点击：n=3,c=0，符合资格。广告 B 有2次曝光、1次点击：n=3,c=1，也是长尾，但不在本轮辅助池中。广告 C 在所有训练前缀里从未出现：n=0,c=0，属于冷启动，不能混称为零点击长尾。

本轮辅助池实测有 1,583,588条广告。有过事件，只说明其 ID 可能通过上下文或负例获得过梯度；没有训练点击，意味着没有以这条广告自身作为点击正目标的学习信号。因此不能简单把“出现过”理解成“已经充分学好了偏好”。

资格池对所有用户使用同一规则。不能先查看用户的真实目标是长尾，再决定给这个用户走长尾通道。检索使用训练统计与可见历史，目标标签只在检索结束后计算指标时使用。

12.3 两条通道共用同一个 q，广告侧看法不同

用户信息与历史仍通过原来的一层因果 Transformer，得到相同的32维查询 q。这次没有训练新的用户塔，也没有改变历史输入。差别只在辅助广告的编码：把显式广告 ID Embedding 那一块设为零，其余13个属性和81号向量照常经过原来的投影与融合层。

用户属性＋可见历史 → 原用户编码器 → 同一个 q：[B,32]
                                      ├→ 主广告表示：ID＋属性＋81 → 原主 Top-500
                                      └→ 辅助广告表示：0＋属性＋81 → 零点击长尾新提议
                                                                      ↓
                                                       固定500预算的保护融合
vmain,i = ReLU(W · [eID,i; e100,i; …; e116,i; Pm81,i] + b)
vaux,i = ReLU(W · [032; e100,i; …; e116,i; Pm81,i] + b)

分号表示拼接。令 C 为这一批候选广告数，仍然是15块32维输入，拼成 [C,480]，由同一融合层变回 [C,32]；不是删掉 ID 后把线性层改成448维。当前每块 C≤8192；用户查询批次则是上图的 [B,32]。W、b、属性 Embedding 和81投影都复用原 checkpoint，没有新增可训练参数。

本项目 padding/OOV 第0行本来就固定为零，因此当前显式零分量与使用该零行在数值上等价。这里没有把“训练出现过、但没点击”的广告重新定义为真正冷启动；只是对辅助候选使用另一种表示视图。

“去掉显式广告 ID”不等于“纯文本语义模型”。原属性仍含121等高基数字段，81也仍是官方提供的表示。准确说法是复用原共享特征、屏蔽显式 ID 分量的候选视图。

12.4 内积与余弦：这次到底比较了什么？

sraw(u,i) = quTvaux,i
scos(u,i) = quTvaux,i / (‖qu‖ · ‖vaux,i‖)

内积同时受方向和长度影响；余弦关注方向。举一个人工设置的二维教学例子：q=(1,0)，A的向量为 (2,2)，B为 (1,0)。原始内积 A得2、B得1，A在前；余弦 A约0.707、B为1，B在前。归一化会改变候选排名，不是保持原内积排序的等价变换。

这里归一化的是经过属性融合、线性层和 ReLU 后的广告输出。原始81输入本来接近单位范数，也不能推出融合后的32维向量是单位向量。对固定用户，归一化 q 只是给全部分数乘同一个正比例，不改变候选顺序；实质差别来自是否归一化各广告 v。

这只是一个辅助评分对照，主通道仍保留原始内积分数与顺序。实际开发比较中 raw_ip 的补尾表现更好，最终锁定了它；不能因为余弦概念更直观就预设它更优。

12.5 子集的第几行，和广告 local ID 是两回事

主目录的 local ID 连续，但筛选出的辅助目录只包含其中一部分。先用一个单独的映射例子：假设符合资格的 local ID 为 [35,90,110]，辅助向量矩阵只有3行：

辅助矩阵行号local ID对应向量
035vectors[0]
190vectors[1]
2110vectors[2]

检索返回辅助行号1，要通过 local_ids[1] 还原为广告90。不能直接用 1+1=2。因此这条子集检索不能照搬前面主 Faiss 索引的行号加1映射。

真正要搜索的集合，还要扣除用户已经见过的广告，以及原主 Top-500 全部广告。后者不是“不喜欢”，而是已经在主候选池里，继续占辅助名额没有增量。

Au = Top25i ∈ E ∖ (Hu ∪ Mu) s(u,i)

E 是资格池，Hu 是可见历史，Mu 是原主500。先过滤、再取25个，保证名额用于真正的新候选。先取25、再发现其中20个已在主列表，会浪费本来可以检索到的后续提议。

{{code:research/tail-recall/taac_retrieval/tail_channel.py:54:93}}
  1. blocked = torch.cat((seen, main), dim=1) 合并两个屏蔽来源。
  2. torch.searchsorted(ids, blocked) 在升序辅助ID里找插入位置。插入位置可能不是实际存在的广告，所以还要比较ID是否相等，得到 valid。
  3. 每块分数为 queries @ vectors[start:stop].T，形状为 [B,block_items]。
  4. 把当前块里需要屏蔽的位置改成 -inf，再取块内 Top-K，与之前的 Top-K 合并。
  5. candidates = ids[start:stop][positions] 立即把子集行位置还原成真正 local ID，后面的融合统一使用 local ID。
  6. 若合法候选不足，非有限分数的位置输出0，代表空提议，不能当成广告。后续融合会跳过0。

这仍是分块精确检索：遍历辅助池所有向量，减少的是候选域和峰值分数矩阵。当前没有新增持久化的辅助 Faiss 索引，也没有新的辅助 ANN 召回率报告。

12.6 固定500个：补进去之前，必须知道谁会被移走

如果保留原500再追加5个，候选池就是505；覆盖上涨可能部分来自预算变大。为了公平，本轮最终仍是500，最多补5个新长尾，同时等量移除原列表末尾的未保护项。

Pu = 主Top-10 ∪ {i ∈ Mu | ni ≤ 5}
m = min(quota, 新提议数, 可移除数)；Fu = 按原序保留(Mu ∖ Du)，再追加 Au 的前 m 项

P 是保护集合；D 从主列表尾部挑选不在保护集合里的 m 个广告。两条排序列表没有直接混加分数，也没有新增学习排序器。保留项沿用主通道原顺序，新辅助项放在末尾。

{{code:research/tail-recall/taac_retrieval/tail_channel.py:96:129}}
  1. used 初始装入全部主广告；只把真正没出现过的新提议加入 novel。
  2. range(len(original)-1, protect_top-1, -1) 从列表末尾向前找；只有 counts[original[i]] > 5 的位置可删除。
  3. take = min(...) 防止提议不足或可删除项不足时强行填满配额。quota是上限，不是必须替换的数量。
  4. 先保留未删除的主候选，再追加同样数量的新候选；applied 记录每个人实际换了几个。

已有冷尾候选不会被删，所以相应 Recall@500 按构造不下降；前10的身份和顺序也不变，所以每人的 HR@10 与 NDCG@10 不变。这是保护机制的结果，不能解释成新模型学会了更好的冷启动表示。

12.8 真实补回案例：辅助第2名，为什么最终是第497名？

{{tail_case}}

这条广告在训练里仅有1次事件、0次点击，符合辅助资格。对原主模型seed2026，它在完整主检索中排在500名之外；辅助检索先排除原500和历史后，将它排在新提议第2位。删去5个未保护项后，剩余主候选占前495位，辅助第1项在496位，第2项就在497位。

融合名次 = 保留的主候选数 + 辅助新提议名次 = 495 + 2 = 497

因此这一次 Recall@500 从0变1，但 HR@10 仍为0。原先已经处于 Top-10 的广告也没动。同一个用户还被另外两个seed对应模型补回，算3次模型命中，却只有1名不同用户。不要把模型重复评估当成新增了3个用户。

12.9 实验为什么先开发选型，再锁定做确认？

新确认行为只用一次。本轮先在已看过的旧10,000人开发队列上，复用三个主模型比较4种组合：raw_ip/cosine × quota1/quota5。配额、评分与门槛提前固定，不临时扩网格找最好数字。

{{tail_protocol_results}}

门槛要求：整体 Recall@500 至少保留主通道的99%；冷启动与有点击长尾不下降；零点击长尾平均严格增加；至少两个模型各自有新增零点击长尾命中。通过后优先选零点击长尾覆盖更高的方案，再比较整体覆盖、小配额和更简单的raw_ip。

12.11 为什么3个人还不足以说“稳定解决了长尾”？

少量目标可能受用户抽样和原模型初始化影响。为保留主通道与融合的配对关系，先计算每个模型、每个用户的命中差值，再有放回抽取模型和用户，共重采样2,000次；每次重新算均值，以2.5%和97.5%分位数作为95%区间。

{{code:research/tail-recall/scripts/run_supplemental_tail.py:222:245}}

零点击长尾差值区间为 [0,+0.5650] 个百分点，全部长尾为 [0,+0.3873] 个百分点；下界触0，不能称为稳定或显著收益。整体差值区间为 [−0.1800,−0.0500] 个百分点，在当前离线抽样设置下覆盖损失明确。三个模型仍共享同一批用户，区间不能代表任意新模型或线上流量。

56项测试、GPU小样本预检和独立结果核验均通过。独立核验重新构造了开发12份、确认3份融合结果，检查总预算500、无重复与历史广告、只新增资格长尾、原冷尾和前10保持，并重新计算指标、选型与区间。测试通过说明实现与记录相符，不代表指标一定更好。

本轮的准确结论是：在固定预算下补回了极少量零点击长尾目标，并付出了整体覆盖代价，保留为实验原型。 不能说解决了冷启动、显著提升了推荐效果，或者已经在线上验证。本章也没有新增训练、生成式模型、独立排序器或辅助Faiss服务。

12.12 面试时，把“你为什么这样做”讲清楚

可以按“发现分桶问题→区分事件频次和点击支持→保留有效主模型→设计共享特征辅助视图→固定候选预算评估互补性→用新留出行为确认并报告代价”的顺序讲。实际贡献是诊断、实现、实验和判断闭环，结果规模与限制也属于你需要理解的内容。

这一章的自测与面试追问

为什么没有训练点击的广告，也可能有自己的ID Embedding？

本项目是否分配独立ID行取决于训练事件中是否出现，曝光或未知事件也算。没有点击不代表没有ID行，但它没有以自身作为点击正目标的监督，仍可能通过历史上下文或负候选得到梯度。

这算两个模型，还是两个召回通道？

这里是两条候选获取路径：共用同一原模型查询和已训练权重，广告侧使用原ID视图与零ID辅助视图。没有训练两个新模型，也不意味着两条通道的候选与目标命中完全独立。

原始81已经归一化，为什么还比较余弦？

81只是融合输入之一，经过投影、属性拼接、线性层与ReLU后的广告向量没有单位范数保证。辅助广告输出归一化会改变排序；此次开发结果仍选择了原始内积。

为什么要在辅助Top-K之前排除整个主500？

辅助的目的在于新增。先排除主列表和历史，再取K，能让前几名提议用于新候选，避免大量重叠候选占满有限名额。

为什么长尾提高了，整体却下降？

500预算固定，新增长尾需要替换原中频、头部候选。本轮平均新增1.67个目标，却丢失13个，因此总体下降。99%容忍门槛只是允许小幅代价，不会把下降变成整体提升。

冷启动和Top-10不下降，是新表示学得更好的证据吗？

不是。它们的候选被规则保护，所以按构造保持。可评估的新增来自零点击长尾；Top-10没有重排，所以不能声称最终十条推荐更好。

三个模型新增1、3、1，为什么不是新增5个用户？

三个模型在同一批人上评估，有用户被多个模型重复补回。实际并集只有3名用户，其中一名被三个模型补回。要同时报告模型命中次数与不同用户规模。

如果接下来真要服务，哪些工程检查仍需完成？

需要构建并保存辅助向量与显式localID映射，测量额外存储和实际请求延迟，验证近似索引损失及模型/索引版本一致性。当前GPU批量精确检索的均摊耗时不能冒充单请求p95。

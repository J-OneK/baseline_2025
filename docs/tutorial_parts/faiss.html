11 · 专题：独立的向量检索链路

把模型变成可复用的 Faiss 检索链路

完整推荐演示使用精确 Top-500。本专题单独复现主召回的 Faiss 直接 Top-10，讲向量导出、MIPS→L2、历史过滤、重合率和延迟。

11.1 离线算广告向量，请求时算用户向量

广告向量只依赖广告本身的 ID、属性和 81 向量，因此同一个 checkpoint 下可离线批量计算并放进索引。用户向量依赖当前历史，在推荐时通过序列编码器计算。两侧最终在同一个 32 维空间里以内积匹配。

11.2 原始内积与余弦相似度

qTv = ‖q‖ · ‖v‖ · cos θ  ;  cosine(q,v) = qTv / (‖q‖‖v‖)

训练优化的是原始内积分数，向量长度也是模型学到的信号。直接把所有广告归一化为单位向量，会移除广告范数对分数的影响，可能改变排名。

教学例：q=(1,0)，广告甲 x₁=(1,0)，广告乙 x₂=(3,1)。

广告原始内积余弦
甲11
乙33/√10 ≈ 0.9487

内积优先乙，余弦优先甲。因此当前代码没有进行单位归一化。若要改成余弦，需要把它作为新的建模/检索实验验证，而不能静默替换。

11.3 为内积排序构造一个等价的欧氏距离问题

MIPS 是 Maximum Inner Product Search，即最大内积检索。历史直接使用 raw-IP HNSW 的验证召回没有达到 98% 门槛，因此采用一个保持精确排名的非对称变换。先选定覆盖全部广告范数的半径平方：

R² = maxi ‖vi‖²

广告向量增加一维，用户查询也增加一维，但构造方式不同：

v′i = [vi, √(R² − ‖vi‖²)]  ;  q′ = [q, 0]

展开两者的平方欧氏距离：

‖q′−v′i‖² = ‖q−vi‖² + R² − ‖vi‖²
= ‖q‖² + R² − 2qTvi

对一次固定查询，‖q‖²+R² 是与广告无关的常数。因此距离越小，原始内积越大。模型仍输出 32 维向量，HNSW 内部索引维度是 33。

{{code:taac_retrieval/ann.py:6:26}}

radius_squared 必须不小于任一广告向量的范数平方；maximum(...,0) 处理舍入误差，不能靠它掩盖明显不合格的半径。Faiss 的 L2 搜索返回平方距离，包装类把它还原为原始内积分数：

score = (‖q‖² + R² − distance²) / 2

手算 q=(1,0)，R²=10：

广告原向量广告升维向量与 q′=(1,0,0) 的平方距离还原内积
(1,0)(1,0,3)9(1+10−9)/2=1
(3,1)(3,1,0)5(1+10−5)/2=3
(0,2)(0,2,√6)11(1+10−11)/2=0

变换保证的是精确距离排名与精确内积排名等价。HNSW 仍然是近似搜索，不能由这条代数恒等式推出它必定找回 100% 的精确结果。实际近似质量要测量。

11.4 HNSW 的三个参数，以及验证门槛

HNSW 把广告向量组织成多层邻接图。上层提供较远距离的跳转，搜索再逐层深入，在底层维护候选集合。它以额外图结构内存和建索引成本，换取查询时少访问许多向量。

参数当前设置直觉
M32控制图连接规模；通常越大，内存和构建开销越高。这里的 M 与训练有效监督位置数 M 无关
efConstruction100构图时的候选搜索宽度，影响图质量与构建成本
efSearch2048查询时的搜索宽度；通常越宽越慢，但更有机会找到精确近邻

ANNRecall@K = (1 / U) ∑u=1…U |ANNu,K ∩ Exactu,K| / K

这个公式的“答案”是同一个模型的精确推荐 ID 集合。若两份 Top-10 重合 9 项，ANNRecall=90%；但真实点击可能在两份列表里都没有出现，此时两者 HR@10 都是 0。ANNRecall 与点击 Recall 衡量不同的问题。

11.5 Faiss 行号、历史过滤与多取候选

索引构建时从 item_vectors[1] 开始，跳过补齐行。Faiss 自动分配从 0 开始的行号，因此完整编号链是：

Faiss row 0 → local ID 1 → catalog_oids[1] → 最终广告 OID
{{code:taac_retrieval/ann.py:29:55}}

filter_results() 依次把 Faiss 行号加 1，删除负行号、当前用户已见广告和重复广告，按原检索顺序保留前 K。它不训练新的分数函数，也不使用真实目标来调整列表。

直接查询十个候选，可能被历史过滤删掉若干个。因此 search_filtered() 请求：

fetch = min(N, K + 当前 batch 中最大的非零历史事件数)

例如主样例测试历史 [1,2,3,4,5,6,6,7] 有 8 个非零位置，尽管只有 7 个不同广告，代码仍按 8 计数；请求 Top-10 时会多取到 18 个，以留出过滤空间。重复历史会造成保守地多取一些候选。

这里实际只检索一次，没有“候选不足就自动循环扩大搜索”或热门广告兜底。过滤后不足 K 个会抛出异常。理解当前保护范围，才能在扩展服务时知道还缺什么。

这一章的自测

32 维模型为什么会保存一个 33 维索引？

广告增加 √(R²−‖v‖²) 一维，查询增加 0 一维，把最大内积转换为最小平方欧氏距离。包装类对外报告的逻辑维度仍为 32。

如果查询网络换成新训练模型，旧索引能继续用吗？

同一个维度不保证向量空间一致。应使用新 checkpoint 重导出广告向量并重建索引；当前 SHA 检查会拒绝普通的模型身份混用。

Faiss 返回 0，可以直接当作 padding 丢掉吗？

不能。索引跳过了向量表 padding 行；Faiss 的 0 对应 local ID=1。负返回行号才是无效项，之后还要做历史与重复过滤。

98.81% ANNRecall 能说明 98.81% 的用户点击被找到了吗？

不能。它说明近似列表与同模型精确列表高度重合。真实目标命中由 HR/Recall/NDCG 单独衡量。

# OneTrans 风格联合排序在纯 DCN 上还有用吗？

**在这批留出用户上，两种 DCN 基础分加入联合排序后的 NDCG@10 都提高。** 纯 DCN 加联合排序和「原融合 + DCN + 联合排序」的整体结果几乎一样。是否保留联合排序，取决于是否接受额外的打分时间；本次没有证据证明它能稳定改善冷启动或长尾。

## 同一批 500 条，做四个对照

| DCN 基础分 | 不加联合排序 | 加联合排序 |
|---|---|---|
| 原融合 + DCN | 旧 `0.9 / 0.1` 固定融合分加 DCN 修正 | 冻结左侧分数，加新训练的历史联合残差 |
| 纯 DCN | 只用 DCN 输出；15 维输入仍包含召回分和内容 MLP 分 | 冻结左侧分数，加新训练的历史联合残差 |

两个基础 DCN 来自[固定融合分消融](../channel_prior_ablation/README.md)的开发选型，分别为第 15 和第 11 轮。联合排序在各自的基础分上从头训练，两个种子分别使用相同的 3,943 / 4,270 个有效候选列表；同一种子复用候选、初始化和训练样本顺序。联合模型的输入与原实现一致：15 维静态特征、候选的 81 号向量、最近 40 条曝光和点击。两版都训练至第 5 轮，使用原学习率、损失与模型配置，在同一 5,000 人开发集上比较轮次及残差系数（0.25、0.5、1）。两个基础分的联合模型最后都锁定第 5 轮、系数 1。

本次只使用原联合排序的 **10,000 人留出确认队列**评估四种方法，不分新用户批次。这些用户不参与排序模型训练或选轮次。队列以前已用于项目中的其他对照；本次沿用其候选和验证点击，没有使用原协议的测试点击。评估时，两种联合模型都只改打分，500 条候选不变。

## 结果

| 10,000 人，两个种子平均 | HR@10 | NDCG@10 | 冷启动 / 长尾命中次数（两种子合计） | 500 条模型打分 p95 |
|---|---:|---:|---:|---:|
| 原融合 + DCN | 2.715% | 0.014622 | 13 / 4 | 0.35 ms |
| 原融合 + DCN + 联合排序 | **2.890%** | 0.015648 | 13 / 6 | 2.87 ms |
| 纯 DCN | 2.725% | 0.014490 | 15 / 4 | 0.34 ms |
| 纯 DCN + 联合排序 | **2.890%** | 0.015674 | 11 / 4 | 2.86 ms |

| 配对对照（后者相对前者） | HR@10 差及 95% 区间（百分点） | NDCG@10 差及 95% 区间 |
|---|---:|---:|
| 原融合 + DCN → 加联合排序 | +0.175 [0.000, +0.330] | +0.001026 [+0.000271, +0.001733] |
| 纯 DCN → 加联合排序 | +0.165 [−0.050, +0.385] | +0.001184 [+0.000387, +0.001932] |
| 原融合 + DCN + 联合排序 → 移除固定融合加法并重训 | 0.000 [−0.140, +0.170] | +0.000026 [−0.000805, +0.000977] |

区间使用原项目配对 bootstrap，对种子和用户重采样，共 2,000 次；训练种子只有两个。Recall@500 全部为 16.565%。RTX 2080 Ti 上计时只覆盖模型调用和分数相加：候选与特征已在设备上，每种子单用户预热 16 次、同步测量 80 次，表中为两种子 p95 四舍五入，不含召回、特征构建、排序和网络。与历史计时的运行状态不同，应比较本表内的差值（约 **+2.5 ms**）。

## 对项目的含义

- **想要一个简单、计算便宜的版本，纯 DCN 就能独立输出 Top-10。** OneTrans 风格模型是可选的增强。两种基础分上，加入联合模型后的 NDCG 差区间都高于零，说明本次不是靠挑某一种融合方式才看到收益；HR 的区间仍包含零。消融量到的是联合模型、候选内容和逐条历史一起加入的效果，不是把收益单独归因于 attention 结构。
- **纯 DCN 加联合排序的整体收益主要来自头部。** 按种子合计，多了 109 次、少了 76 次前十命中，净增 33 次。头部净增 38 次，中频减少 1 次，冷启动减少 4 次，长尾不变。样本量小，不能把它作为解决冷尾的方案。
- **是否固定加原融合分，对两条完整链路的整体结果未见稳定差异。** 两版最终都命中 578 次，命中的用户并非完全相同。纯 DCN 仍使用两个旧分作为特征，因此去掉输出上的固定加法不等于省掉上游召回或内容 MLP。发布版选择纯 DCN 加联合排序。[固定权重与运行入口](../../docs/ranking_extension.md)；旧链路保留 `--legacy` 复查。

从仓库根目录运行，依赖上一轮 DCN 消融权重及排名记录、原通道排序缓存、联合排序的 10,000 人候选。新一轮输出请用不同目录：

```bash
.project_venv/bin/python scripts/ablate_sequence_rank.py --stage fit --device cuda:0 \
  --output artifacts/sequence_base_ablation_rerun
.project_venv/bin/python scripts/ablate_sequence_rank.py --stage confirm --device cuda:0 \
  --output artifacts/sequence_base_ablation_rerun
```
